# v1.0

The first release put in front of testers. Set `RELEASE=v1.0` (the default).

**What it does.** Upload a claim's PDFs; background pipeline extracts the fields (OCR with a vision
fallback), finds the governing policy clauses, runs fraud and anomaly rules and drafts a cited
recommendation; the adjuster verifies it against the documents and decides, with a reason code for
any override. Every step is in an append-only audit log.

**Measured offline** (frozen test set, 160 claims; see `RESULTS.md`).

**Known issues going into the pilot**
- Policy numbers written with a space (`POL-PREM 672961`) are escalated rather than normalised.
- A claim whose vehicle model is not in the documents is escalated, because the duplicate check
  cannot run.
- A one-digit misread of a scanned policy number can look valid; the console asks the adjuster to
  confirm scan-read fields.

**Feedback that motivated changes:** none yet; no sessions have been run.
